# Security Policy

PocketAuthor handles workflows that can involve manuscripts, source material, publishing metadata, collaboration, authentication, and production systems. Security reports are taken seriously.

## Please do not report vulnerabilities in a public issue

A public issue can expose users before a fix is available.

If GitHub private vulnerability reporting is enabled for the affected repository, use it. Otherwise use the private support/contact path published by PocketAuthor at:

https://www.pocketauthor.com/support

Include:

- affected repository, route, endpoint, or component
- vulnerability type
- reproduction steps
- impact
- proof of concept where safe
- suggested mitigation if known

Do not include unnecessary personal data or other users' manuscript content.

## Good-faith research

Please avoid:

- accessing data that is not yours beyond what is necessary to demonstrate the issue
- modifying or deleting production data
- disrupting service availability
- social engineering
- credential stuffing
- publishing exploit details before remediation
- testing third-party providers in ways that violate their terms

## Secrets

If you discover a committed credential, token, service-role key, private URL, or other secret, report it privately. Do not reuse or validate the credential beyond what is necessary to identify the exposure.

## Scope

Repository-specific security policies override this shared policy when present.
